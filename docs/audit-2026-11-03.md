# Codebase audit, 2026-11-03

Scope: `main` (all code branches are already merged into it), plus the 3 unmerged draft branches, which contain content only.
Method: 5 parallel read-only reviewers, one per area. For every item marked **verified**, the finding was then re-checked against the code or reproduced at code level.
No browser pass was done, so UI items are code-derived, not seen rendered.
Checks run: `tsc` clean for cms-studio and main-portal; cms-studio tests pass (161/161); `validate-content` passes.

Legend: **V** = verified by re-reading the code or reproducing it. **R** = reported by a reviewer with confidence ≥7, but not independently re-checked.

## Critical: governance and permission bypasses (cms-studio backend)

| # | Where | Problem | Status |
|---|---|---|---|
| 1 | `lib/github.ts:560` | Quorum uses the reviewer's **highest role in any vertical**. Being Head anywhere lets a user merge a Member post alone in a vertical where they are only a Deputy. A Head's approval also ignores the author's role: Superadmin and Head posts should need a Superadmin. | V |
| 2 | `lib/github.ts:619` | `approveAndMergePR` squash-merges the **whole PR** without checking its files. A member can open a PR on GitHub that changes `content/club/roles.json` or `.github/workflows/*` alongside an article, and deputies or a head of that vertical can merge it. Vertical also falls back to the PR title or branch name when no `.md` is found. | V |
| 3 | `api/posts/draft/route.ts` + `lib/github.ts:92` | Sending `existingBranch` without `pullNumber` skips the ownership check, so any author can commit onto **another author's draft branch** (IDOR). | V |
| 4 | `api/roles/route.ts:206-227` | Deputy and member assignment check `roleInfo.role` (highest role anywhere) + `verticals.includes`, not the role **in that vertical**. A Head of A who is a member of B can appoint deputies in B. | V |

| 9 | `api/posts/draft/route.ts:221` | A Superadmin revision rewrites `author` in the frontmatter, then that Superadmin can approve their own text (the self-review check only compares against the PR opener). | R |

## Medium

- **CI commit check is bypassable.** Any message starting with "Merge " skips all rules, PR runs only check the synthetic merge commit, and pushes only check HEAD (`verify-commit.mjs:20`). **R**
- **Global scrapbook CSS removes link styling.** Unlayered `a{color:inherit;text-decoration:none}` and the `body` font in `scrapbook.css` override Tailwind on article pages, so links are invisible (WCAG 1.4.1). **R**
- **CMS article feed is unreachable from home.** The nav "blogs" item goes to `/blogs`, which renders hard-coded sample blogs. Real `/blog` posts can't be reached from home. **R**
- **Broken `blob:` cover image on main.** `content/club/posts/test-save-draft.md` has a `blob:` URL cover (always broken), and the validator accepts any string. Test posts (`test.md`, `hi.md`, `test-2.md`, …) are publicly listed. **V**
- **Validator misclassifies posts.** `isEvent = path.includes("events")`, so posts with "events" in the name skip post validation. Typo'd vertical folders, `.mdx` and `isWipDraft` also pass CI. **R**
- **Reviews page shows actions the API rejects.** Approve and Reject are gated on the highest role, not the role in that vertical, so the API returns 403. A deputy's approve on a deputy's PR still posts a GitHub APPROVE review before failing. Applications show Approve/Reject that always 403 for head or deputy requests. **R**
- **Reviewer preview can be covered by author content.** The sanitizer allows any `class`, so author HTML can overlay the reviewer preview using Studio's own Tailwind classes. `![x](/api/auth/logout)` logs reviewers out, because logout accepts GET. **R**
- **Lost updates on concurrent role writes.** Concurrent `roles.json` writes overwrite each other: there is no sha check, and the fallback writes two non-atomic commits. **R**
- **Back button freezes the home page.** Pressing Back after a sticky-note transition restores a frozen full-screen overlay from the back-forward cache. **R**
